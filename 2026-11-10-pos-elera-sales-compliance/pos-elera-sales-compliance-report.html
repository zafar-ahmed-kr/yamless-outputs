Analyst Notes and Recommendations

1. Re-run with --llm to Add MongoDB + RabbitMQ Modules

The static analyzer returned confidence: high for runtime, secrets, and shape. However, two significant runtime dependencies — MongoDB and RabbitMQ — were not detected because the static scanner does not pattern-match NoSQL databases or AMQP brokers. Running the full pipeline with ANTHROPIC_API_KEY set will invoke the LLM gap-filler, which reads source files and infers these dependencies from context. Adding these would materially change the generated infrastructure.

yamless generate /path/to/pos-elera-sales-compliance --out-dir ./output --validate

2. Add MongoDB Module to Generated Terraform

Once the gap-filler detects MongoDB, the renderer should emit an Azure Cosmos DB for MongoDB module. Cosmos DB provides MongoDB wire-protocol compatibility with Azure-native management, private endpoints, and automatic indexing. The golden profile azure-cosmos-db.json covers this resource type.

Expected additional cost: ~$25–$100/mo (serverless tier) or ~$600+/mo (provisioned throughput).

3. Add RabbitMQ / AMQP Module

RabbitMQ is not a native Azure service. Options for the generated Terraform:

  • Azure Service Bus — if the team can migrate AMQP clients to AMQP 1.0 (Service Bus is AMQP 1.0 compatible; RabbitMQ is AMQP 0-9-1). Preferred cloud-native path; already supported by the yamless servicebus module.
  • Self-hosted RabbitMQ on AKS — if AMQP 0-9-1 is required. Outside yamless' current scope.

Consider opening a backlog item to add RabbitMQ/AMQP detection in analyzer/dependencies.py.

4. PingFederate + PingOne Dual-IdP Pattern

The 17 Ping-related secrets indicate simultaneous integration with both PingFederate (enterprise on-premises SSO) and PingOne (cloud SSO). All Ping secrets are correctly identified and will be stored in Azure Key Vault. The security team should review whether duplicate issuer URIs (PING_AUTH_ISSUER_URI vs PING_FED_AUTH_ISSUER_URI) represent intentional dual-validation or a configuration redundancy.

5. Kount Fraud API

KOUNT_API_KEY and KOUNT_BASE_URL are correctly detected and will be stored in Key Vault. No additional infrastructure needed.

6. High Secret Count (43)

43 secrets reflects the complexity of this microservice's external integrations: dual IdP, MongoDB, RabbitMQ, Redis, Kount, ELERA POS, compliance logging, and Spring Cloud Config. All 43 will be stored in Azure Key Vault. Consider auditing for duplicates — MONGODB_URI and SPRING_DATA_MONGODB_URI likely point to the same host, and several PING_* / PINGFED_* variables may be redundant config aliases.
